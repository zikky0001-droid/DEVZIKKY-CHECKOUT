DEVZIKKY PAY / DATA & TRANSPARENCY

Privacy deserves clarity.

This page describes the main categories of information the application is designed to handle. It is a plain-language product overview, not legal advice or a substitute for any formal privacy notice required for a particular business or jurisdiction.

WHAT THE APP HANDLES

Information is used for specific product functions.

The application separates private transaction records from public aggregate statistics. Payment references may appear in public activity reports; optional notes remain private unless the payer explicitly opts in to sharing. Customer names, email addresses and administrator credentials are not published.

▤

Transaction records

Where a transaction has been created, the backend may store the customer's name and email, reference, amount, original currency, transaction type, optional note, source, status and timestamps. Full transaction records are available only through authenticated administrative routes. A transaction reference is used in public activity reporting, and an optional note is exposed publicly only when its payer explicitly consents at checkout.

◈

Payment provider data

Paystack is the payment processor used by the existing integration. The existing integration supports server-side verification and was designed for secure payment initialization. Payment initialization is handled by the server-side Paystack integration. Do not enter or send card details in a note, email or support message.

⌁

Technical and diagnostic logs

Server logs include request IDs, route names, HTTP methods, response statuses, durations and sanitized error messages. Browser reports can include the page path, a resource path, error category and line/column numbers. The error-report endpoint is designed not to receive form bodies, cookies or payment credentials.

▣

Administrator session

After a successful admin login, the server sets an HttpOnly, Secure, SameSite=Lax session cookie. The administrator key is sent only to the same-origin login endpoint and is not added to browser diagnostic report payloads. After a successful login, the form is cleared.

PUBLIC VISIBILITY

What visitors can and cannot see.

01
Public statistics are aggregated.

The statistics page shows totals, currency groupings and payment references. A note appears only when the payer actively selected the public note-sharing option; names and email addresses are never shown.

02
Administrator records are protected.

Transaction listings and CSV export require a valid administrator session. Do not share the admin key or leave an authenticated session open on a shared device.

03
Browser diagnostics are limited.

The browser reporter caps the number of reports per page and strips query strings and common credential patterns. If the visitor is offline or the reporting endpoint is unavailable, a browser error may not reach Vercel logs.

04
Retention follows server configuration.

The backend applies its configured transaction-retention policy during eligible requests. The current project configuration specifies a three-year retention period.
