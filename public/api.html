DEVZIKKY PAY / PUBLIC DEVELOPER REFERENCE

🔌 Public API.

A reference for public-safe GET endpoints and authenticated server-to-server transaction endpoints. Public routes expose no donor identities or private notes; automation routes require the API key.

🟢 SERVICE STATUS

🔌 GET /api/ping

Lightweight liveness check. Does not require a database connection.

{
  "ok": true,
  "status": "alive",
  "service": "DEVZIKKY PAY"
}
🩺 READINESS

🔌 GET /api/health

Checks database readiness, required schema and configuration presence. Secret values are never returned. Detailed database errors remain in the logs.

💳 PAYMENT LIMITS

💳 GET /api/payment-limits

Returns the current configured NGN minimum and maximum transaction amounts, whole-number input policy and checkout toast duration.

{
  "currency": "NGN",
  "minimum_amount_ngn": 100,
  "maximum_amount_ngn": 5000000,
  "whole_numbers_only": true,
  "toast_duration_ms": 5000
}
💱 EXCHANGE RATES

🔌 GET /api/rates

Returns supported currency units per one Nigerian naira (base=NGN). NGN is represented by base and is not duplicated inside rates.

GET /api/rate is a compatibility alias for this endpoint. 
{
  "base": "NGN",
  "source": "live",
  "rates": {
    "USD": 0.000743,
    "EUR": 0.000663
  }
}

Fallback responses may include a snapshot date. These are reference rates, not guaranteed payment quotes.

📊 PUBLIC STATISTICS

🔌 GET /api/stats

Aggregated payment totals and time series. Supported query parameters:

  • from and to — DD/MM/YYYY
  • grain — day, week, month or year
  • download=json — return a pretty-printed JSON attachment
GET /api/stats?from=01/11/2026&to=11/11/2026&grain=day
📤 PUBLIC ACTIVITY EXPORT

🔌 GET /api/stats/export

Returns successful payment references, amounts, types, Lagos timestamps and donor notes only when the donor explicitly opted in. Donor names, email addresses and private notes are excluded.

GET /api/stats/export?from=01/11/2026&to=11/11/2026
🔐 SERVER-TO-SERVER TRANSACTIONS

🔌 POST /api/automation/initialize

Creates a Paystack checkout link for an NGN transaction. Requires the existing API_KEY environment variable in the Authorization: Bearer header.

Required: amount — whole-number NGN amount from 100 through 5000000, inclusive. Numeric values and digit strings (including correctly grouped values such as "5,000") are accepted; decimal values are rejected.

Optional: name (maximum 20 characters), email (maximum 50 characters), and note (maximum 200 characters). Each must be a string, null, or omitted. An empty/whitespace value or the literal string "null" uses its default.

curl -X POST "https://devzikkycheckout.myng.net/api/automation/initialize" \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -H "Content-Type: application/json" \
  --data '{"amount":1500,"name":"Anonymous","email":"billing@example.com","note":"Automation"}'
POST /api/automation/initialize
Authorization: Bearer YOUR_API_KEY
Content-Type: application/json

{

  "email": "billing@example.com",
  "note": "Automation"
}

🔎 SERVER-TO-SERVER VERIFICATION

🔌 POST /api/automation/verify

Verifies a previously created transaction directly and returns the server-confirmed state.

curl -X POST "https://devzikkycheckout.myng.net/api/automation/verify" \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -H "Content-Type: application/json" \
  --data '{"reference":"DZP-..."}'
POST /api/automation/verify
Authorization: Bearer YOUR_API_KEY
Content-Type: application/json

{
  "reference": "DZP-..."
}

A processed check returns HTTP 200 for all known payment states. ok: true means the verification request completed; it does not mean payment succeeded. Only paid: true confirms a verified success. The amount is expressed in naira, not kobo.

{
  "ok": true,
  "reference": "DZP-...",
  "payment_status": "success",
  "paid": true,
  "amount": 1500,
  "currency": "NGN"
}

Possible states: success, failed or pending (an existing record already marked reversed may return reversed). Paystack processing/unknown states stay pending. A timeout or upstream verification failure returns HTTP 503 with VERIFICATION_UNAVAILABLE; retry it and do not mark the payment failed. Unknown references return 404 TRANSACTION_NOT_FOUND; invalid or missing references return HTTP 400. Payment status is established by the server's Paystack verification, not by a status supplied by the caller.

🔢 PAYMENT AMOUNT RULE

🔌 Integer amounts only

Payment initialization accepts whole-number amounts only. API clients may send an ungrouped integer such as 5000 or a correctly grouped value such as 5,000. Decimal inputs are rejected; the backend independently validates the amount and converts to NGN value.

{
  "success": false,
  "error": {
    "code": "AMOUNT_WHOLE_NUMBER_REQUIRED",
    "message": "Only whole-number amounts are accepted.",
    "whole_numbers_only": true,
    "minimum_amount_ngn": 100,
    "maximum_amount_ngn": 5000000
  }
}
🔑 AUTHENTICATION MODEL

🔌 Keep credentials private

Public GET endpoints do not require a secret key. Both POST /api/automation/initialize and POST /api/automation/verify require the existing API_KEY environment variable as Authorization: Bearer YOUR_API_KEY.

🛡️ NOT IN THE PUBLIC CATALOGUE

🧭 Private and state-changing routes

Admin transaction, export and server log endpoints remain restricted to their existing authenticated Admin sessions.
